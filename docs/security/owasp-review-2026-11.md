# OWASP Top 10 review — 2026-11-26

| OWASP                         | Finding                                                                                                                                                                                                                 | Resolution                                                                                                                                                                                                                                                                                          |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A06 Vulnerable components     | `pnpm audit --prod` reported 6 critical / 49 high (Next.js, Fastify, `@fastify/multipart`, zod and transitive `fast-uri`, `brace-expansion`, `nanoid`, `@fastify/busboy`; `shadcn` CLI shipped as a runtime dependency) | Upgraded Next 16.4.6, Fastify 5.12.8, `@nestjs/*` 11.2.4, `@fastify/multipart` 10.1.9, zod 4.6.7; pinned patched transitive versions through `pnpm.overrides`; moved `shadcn` to `devDependencies`. Result: 0 critical / 0 high in production dependencies (11 moderate, 4 low remain, transitive). |
| A07 Authentication failures   | `POST /auth/session` had no brute-force protection                                                                                                                                                                      | Failed-login limiter: 5 failures / 15 min per client address and 50 globally, `429` with `Retry-After`.                                                                                                                                                                                             |
| A05 Security misconfiguration | No security headers on web or API                                                                                                                                                                                       | Web: CSP, `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, HSTS in production, `X-Powered-By` removed. API: `nosniff`, `X-Frame-Options`, `Referrer-Policy`, restrictive CSP, default `Cache-Control: no-store`, HSTS in production.                                          |
| A10 SSRF                      | Outbound webhook URL validation missed `0.0.0.0`, CGNAT, IPv6 (`::1`, `fc00::/7`, `fe80::/10`, IPv4-mapped) and `*.internal`/`*.local`                                                                                  | `isPrivateHost` now rejects these literals. Hostnames that resolve to private addresses must still be blocked by network egress policy.                                                                                                                                                             |
| A03 Injection                 | Reviewed dynamic SQL fragments (`limit`/`offset`, identifier quoting)                                                                                                                                                   | No injection found; values are parameterized or numerically sanitized.                                                                                                                                                                                                                              |
| A01/A02/A08                   | Session cookie is `HttpOnly`, `SameSite=Lax`, `Secure` on HTTPS; unsafe API methods require matching `Origin`; inbound webhooks use HMAC with `timingSafeEqual`                                                         | No change required.                                                                                                                                                                                                                                                                                 |

Follow-ups: the environment-based single-user login has no MFA; the in-memory limiter is per web instance.

Telegram settings (A02): the bot token is encrypted at rest and write-only; see `docs/runbooks/telegram-notifications.md`.
